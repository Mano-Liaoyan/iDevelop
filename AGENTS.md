# iDevelop

English is the project's working language. Use English for project discussions and agent responses, documentation, code comments and interface text, issues, and commit and pull request text, even when the user's message is in another language. An explicit request for another language applies to that task. Preserve identifiers, source quotations, and required localized content when accuracy requires it.

This repository contains the development setup and a C# and Avalonia desktop app for one project's workflow, in PlanWeave's look with a light and a dark theme. The app runs tasks with Claude Code, Codex, Pi, or Antigravity CLI: Run Workflow runs a whole workflow along its dependency connections, and a node's Run runs that node and then each node after it once all of that node's predecessors are complete. The rest of workflow execution is being built; its design is the record linked from `docs/context.md` and the map issue #54. Team synchronization and cross-provider orchestration remain undesigned. Do not invent product architecture beyond `docs/product-direction.md`, the linked records, and the ADRs.

Engineering work uses Matt Pocock's skills (the `mattpocock-skills` plugin) with GitHub Issues as the tracker; `docs/development-environment.md` describes the setup and workflow. Read `docs/context.md` and the records it links before changing the project.

Record a settled architecture or product decision as an ADR under `docs/adr/`, and settled vocabulary in `GLOSSARY.md`, through the domain-modeling skills. The older decision records under `docs/handoffs/` stay until the project docs say everything in them that still matters; Git history keeps a deleted record. `node scripts/check-handoffs.mjs` fails on a record that neither `docs/context.md` nor `docs/product-direction.md` links, and on an inline link in either that names a missing record. Keep credentials, private transcripts, and personal account configuration out of committed files and issues.

Concurrent writers use separate Git worktrees and branches. Never run `git submodule deinit` inside a worktree. Never run real coding-agent clients as app tasks without the owner's explicit approval; tests use the repo's fake agent.

For application changes, run `dotnet build -c Release`, `dotnet test -c Release`, `node scripts/check-licenses.mjs`, `node scripts/planweave-tokens.mjs --check`, and `node scripts/fluent-icons.mjs --check`. On Windows, also verify application changes in the real window with the `verify-idevelop` skill. For documentation changes, run `node scripts/check-handoffs.mjs`. GitHub Actions is disabled by the owner, so these local checks are the gate.
