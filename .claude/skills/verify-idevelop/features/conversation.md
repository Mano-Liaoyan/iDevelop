# Talk to a task's agent

A user writes to a task's agent from the composer in the `Talk to the Agent` section of the inspector. A message sent while a turn runs waits for that turn to end, and the next turn resumes the client's session with it. Stop and send stops the running turn's process tree first, and the next turn starts at once. A message to a task that is not running continues its last session in a new attempt, and the conversation then shows the earlier attempt above the new one. While a task waits for the person, Open in terminal copies the client's own command for the session, after a change into the project folder, and the inspector says that turns taken there are not in iDevelop's record.

## Sub-features

- `talk-terminal` copies `Set-Location -LiteralPath '<project>'; codex resume <session>`, says so in the status bar, and records the hand-off on the last attempt.
- `talk-continue` sends a message to a task that is not running and starts a new attempt that resumes the last attempt's session.
- `talk-chain` shows the earlier attempt's status line, reply, and hand-off note above the continuation.
- `talk-queue` keeps a message sent during a turn under `Waiting for the turn to end` until the turn ends.
- `talk-stop` stops the running turn's process tree and starts the next turn with every waiting message, joined by a blank line.
- `talk-keys` sends with Ctrl+Enter, while Enter starts a new line. It needs keys, so `ConversationTests.Ctrl_Enter_in_the_composer_continues_a_finished_run_in_a_new_attempt_and_Enter_starts_a_new_line` covers it headlessly.

## How to get to it (user POV)

- Choose a task in the sidebar or on the canvas, write in the composer in the `Talk to the Agent` section, and choose `Send` or press Ctrl+Enter.
- While the task runs in this window, write in the composer and choose `Stop and send`.
- While a task waits for you, choose `Open in terminal`. A task waits after a turn when its conversation is `Chat`, or when it is `May ask` and the agent asked.

## Driving it with real-window.psm1

Preconditions:

- A new session on the sample, started with `$s = Start-IDevelop`, so runs go through the fake Codex.
- `Wait-Until { (Find-ById $s.Window 'AgentCodex').Current.Name -like 'Ready*' } 60` has returned `$true`.
- `$s.Gate` exists. Run `New-Item -ItemType File $s.Gate`. Every turn of the fake Codex, fresh or resumed, starts a sleeper, writes its id to `$s.Run\fake-bin\sleeper.pid`, and waits until `$s.Gate` exists. Then it replays a successful turn that reports session `01a104d5-d442-71a1-9b08-8938c119e5ae` and ends with `DONE`.
- A call that lists texts first runs `$text = [System.Windows.Automation.PropertyCondition]::new([System.Windows.Automation.AutomationElement]::ControlTypeProperty, [System.Windows.Automation.ControlType]::Text)`.

- **First run.** Choose the second task, set its conversation to Chat, and run it. Run `Select-Element (Get-SidebarTasks $s.Window)[1]`, `Select-PickerEntry $s 'TaskConversation' 'Chat'`, and `Invoke-Element (Find-ById $s.Window 'RunTask')`. Then run `Assert-Step $s ((Wait-Until { (Find-ById $s.Window 'LastRunStatus').Current.Name -eq 'Waiting for you' } 30) -eq $true) 'the first run waits for you'`, `Assert-Step $s ((Get-Value (Find-ById $s.Window 'LastRunResult')) -eq 'DONE') 'its reply is DONE'`, `Assert-Step $s ((Find-ById $s.Window 'OpenInTerminal').Current.IsEnabled) 'Open in terminal is offered'`, and `Assert-Step $s ($null -eq (Find-ById $s.Window 'StopAndSend' 1)) 'Stop and send shows only during a turn'`.
- **Open in terminal.** Run `$command = "Set-Location -LiteralPath '$($s.Project)'; codex resume 01a104d5-d442-71a1-9b08-8938c119e5ae"` and `Invoke-Element (Find-ById $s.Window 'OpenInTerminal')`. Then run `Assert-Step $s ((Wait-Until { (Get-Clipboard) -eq $command } 10) -eq $true) 'the clipboard holds the command'`, `Assert-Step $s ((Find-ById $s.Window 'Status').Current.Name -eq "Copied $command. Paste it in a terminal to continue this session in $($s.Project).") 'the status bar names the command and the folder'`, and `Assert-Step $s ((Find-ById $s.Window 'TerminalNote').Current.Name -like "Opened in a terminal in $($s.Project) at *. Turns taken there are not in iDevelop's record.") 'the inspector notes the hand-off'`. `LastRunStatus` still reads `Waiting for you`. Run `Save-Evidence $s 'handed-off'`. The last line of `$s.Run\handed-off\attempts\**\events.jsonl` has `type` `handedToTerminal`, `folder` `$s.Project`, and `command` `$command`. Then run `Invoke-Element (Find-ById $s.Window 'MarkDone')`, `Assert-Step $s ((Wait-Until { (Find-ById $s.Window 'LastRunStatus').Current.Name -eq 'Succeeded' } 10) -eq $true) 'Mark done finishes the run'`, and `Select-PickerEntry $s 'TaskConversation' 'Autonomous'`, so the next run does not wait.
- **Continue.** Close the gate, so the resumed turn waits. Run `Remove-Item $s.Gate`, `Set-Text (Find-ById $s.Window 'Composer') 'banana'`, and `Invoke-Element (Find-ById $s.Window 'SendMessage')`. Then run `Assert-Step $s ((Wait-Until { (Find-ById $s.Window 'LastRunStatus').Current.Name -eq 'Running' } 30) -eq $true) 'Send continues the finished run'` and `Assert-Step $s ((Get-Value (Find-ById $s.Window 'Composer')) -eq '') 'the composer clears'`. Run `Save-Evidence $s 'continued'`. Read the newer attempt's first line with `$newest = Get-ChildItem "$($s.Run)\continued\attempts" -Recurse -Filter events.jsonl | Sort-Object { $_.Directory.Name } | Select-Object -Last 1` and `$requested = Get-Content $newest.FullName -TotalCount 1 | ConvertFrom-Json`. Its `prompt` is `banana`, `continues.session` is `01a104d5-d442-71a1-9b08-8938c119e5ae`, `arguments[1]` is `resume`, and `command` is `$s.Run\fake-bin\codex.CMD`.
- **Chain.** Read the conversation. Run `$lines = @((Find-ById $s.Window 'Conversation').FindAll('Descendants', $text).Current.Name)`. It holds five lines: `Succeeded · Started … · took … s`, `Opened in a terminal in <project> at …. Turns taken there are not in iDevelop's record.`, `Running · Started …`, `You`, and `banana`. Run `Assert-Step $s ($lines.Count -eq 5 -and $lines[0] -like 'Succeeded · Started *' -and $lines[1] -like "Opened in a terminal in $($s.Project) at *" -and $lines[2] -like 'Running · Started *' -and $lines[3] -eq 'You' -and $lines[4] -eq 'banana') 'the earlier attempt and its hand-off stay above the continuation'` and `Assert-Step $s ((Get-Value (Find-ById $s.Window 'TurnReply1')) -eq 'DONE') 'the earlier reply stays'`. `Find-ById $s.Window 'TerminalNote' 1` returns `$null`, because the hand-off belongs to the earlier attempt.
- **Send during a turn.** Run `Set-Text (Find-ById $s.Window 'Composer') 'and an apple'` and `Invoke-Element (Find-ById $s.Window 'SendMessage')`. Then run `Assert-Step $s ((Wait-Until { (Find-ById $s.Window 'WaitingMessages' 1).Current.Name -eq 'Waiting for the turn to end' } 10) -eq $true) 'the message waits for the turn'` and `Assert-Step $s ((@((Find-ById $s.Window 'WaitingMessages').FindAll('Descendants', $text).Current.Name) -join '|') -eq 'and an apple') 'the waiting list holds the message'`. `LastRunStatus` still reads `Running`, and `Find-ById $s.Window 'StopAndSend' 5` finds the button. Run `Save-Evidence $s 'waiting'`.
- **Stop and send.** Read the running turn's sleeper with `$sleeper = [int](Get-Content "$($s.Run)\fake-bin\sleeper.pid")`. Run `Set-Text (Find-ById $s.Window 'Composer') 'Stop. Use a pear.'` and `Invoke-Element (Find-ById $s.Window 'StopAndSend')`. Then run `Assert-Step $s ((Wait-Until { -not (Get-Process -Id $sleeper -ErrorAction SilentlyContinue) } 30) -eq $true) 'Stop and send stops the turn and what it started'` and `Assert-Step $s ((Wait-Until { -not (Find-ById $s.Window 'WaitingMessages' 1) } 30) -eq $true) 'the waiting messages went to the next turn'`. Run `$lines = @((Find-ById $s.Window 'Conversation').FindAll('Descendants', $text).Current.Name)`. Its last three lines are `You stopped this turn.`, `You`, and ``"and an apple`n`nStop. Use a pear."``. `LastRunStatus` still reads `Running`, because the next turn waits for the gate.
- **Finish.** Open the gate. Run `New-Item -ItemType File $s.Gate`. Then run `Assert-Step $s ((Wait-Until { (Find-ById $s.Window 'LastRunStatus').Current.Name -eq 'Succeeded' } 30) -eq $true) 'the next turn succeeds'` and `Assert-Step $s ((Get-Value (Find-ById $s.Window 'LastRunResult')) -eq 'DONE') 'its reply is the result'`. `Find-ById $s.Window 'TurnReply2' 1` returns `$null`, because the stopped turn has no reply. Run `Save-Evidence $s 'conversation'`. The newest attempt's types are `requested`, `launched`, `messageQueued`, `messageQueued`, `exited`, `turnRequested`, `launched`, four `agent` lines, and `exited`. The second `messageQueued` has `stopsTurn` `true`, and the `turnRequested` line's `prompt` is ``"and an apple`n`nStop. Use a pear."``.

## Gotchas

- Never paste the copied command into a terminal. `codex` there is the user's real Codex, which spends quota and has no session with the fake's id.
- Open in terminal replaces the text on the Windows clipboard. While another program holds the clipboard, the status bar starts with `iDevelop could not copy the command.` and shows the command, and the hand-off is still recorded. `ConversationTests.When_the_clipboard_fails_Open_in_terminal_shows_the_command_to_run_and_still_records_the_hand_off` covers that path headlessly.
- The gate decides when each turn ends. While it exists, every turn ends at once, so no message can wait and `Stop and send` never shows. Remove it before Continue.
- Each turn rewrites `sleeper.pid`. Read it after the turn starts and before the next one. A turn that ends on its own leaves its sleeper running, and `Stop-IDevelop` stops it.
- `StopAndSend`, `WaitingMessages`, `TerminalNote`, and a reply box with no reply exist only while shown, so `Find-ById` returns `$null` for them otherwise. Pass a short timeout.
- A reply is an `Edit` element, read with `Get-Value`. The latest turn's reply is `LastRunResult`, and each earlier reply is `TurnReply<n>`, numbered across the whole conversation. Status lines, notes, `You`, and the person's messages are `Text` elements.
- Status lines show local times in the machine's format, so match them with `-like`.
