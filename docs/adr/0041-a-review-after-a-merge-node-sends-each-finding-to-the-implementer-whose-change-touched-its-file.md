# A review after a Merge node sends each finding to the implementer whose change touched its file

A review whose subject is a Merge node sends each round's findings to the implementers behind the merge, not to the Merge node's agent. The owner reported on 2026-10-25, in a workflow where "Implement calculator engine" and "Implement Avalonia.FuncUI" go into "Merge engine and UI", then "Review the integrated…" and "Approve the calculator", that the review's Changes Needed sent finding 1 at `src/Calculator.App/Views.fs:80` to the Merge node's agent: "the review agent sends feedback to the merge agent which is nonsense, it should send back to the implementation agent." Asked the questions below on 2026-10-25, they answered:

- **"In Implement engine + Implement UI → Merge → Review, which implementation agent gets a finding?"** By file: a finding goes to the implementer whose change touched its file, so `Views.fs:80` goes to Implement UI. Each agent sees only its findings.
- **"A finding whose file both implementers touched, or neither did (e.g. a new file, or only the merge's conflict fix touched it): who gets it?"** Every implementer: it goes to each implementer behind the merge.
- **"After the implementers' fixes, how does the next round reach the reviewer?"** Merge again: the Merge node merges the new commits, its agent running only on a conflict ([ADR 0033](0033-a-merge-node-resolves-a-runs-conflicts-and-a-finished-run-merges-into-its-branch.md)), and then the reviewer reviews the new merge.

## How it works

In Implement engine → Merge, Implement UI → Merge, then Merge → Review → Approve, the engine's change touched `src/Calculator.Core/Engine.fs`, the UI's change touched `src/Calculator.App/Views.fs`, and the reviewer's round 1 lists finding 1 at `src/Calculator.App/Views.fs:80` and finding 2 at `docs/usage.md:3`:

- **The implementers.** A review's implementers are the editing agents behind its Merge node, through any Merge node before it. A review whose subject is an editing agent sends its findings to that agent, as before. The review still takes one subject, the Merge node, and its reviewer still reads the Merge node's ticket, its report, and the merge's change ([ADR 0037](0037-a-review-after-a-merge-node-reviews-the-merge.md)).
- **By file.** A finding's file is its location without the line, so finding 1's is `src/Calculator.App/Views.fs`. A change touched a file when the file differs between the base the implementer's first result started from and its newest result when the reviewer's round ended. Finding 1 goes to Implement UI alone. Finding 2's file is one neither change touched, so it goes to both, and so does a finding whose file both changes touched, or whose location names no file.
- **Each implementer's fix.** Implement UI's fix round prompt lists findings 1 and 2, and Implement engine's lists finding 2. Each fix is an attempt of its implementer in its own worktree, which resumes its session as any fix does, and each starts beside the run's other clients. An implementer that gets no finding runs no fix, and the Merge node's agent gets none.
- **Merge again.** Each fix's result supersedes its implementer's earlier one, so the Merge node's merge goes out of date and its own step merges again once every implementer is done ([ADR 0034](0034-a-retry-merges-new-inputs-into-its-earlier-change-and-an-out-of-date-task-runs-again.md)). Its agent runs only when that merge conflicts.
- **The next round.** Once every fix of the round ended and the new merge is handed on, the reviewer's next turn reads each implementer's report and the new merge's change since the merge it read before. A finding both implementers answered counts as disputed when either disputed it.
- **The loop's other rules hold for each fix.** A round that repeats an earlier round waits for the person ([ADR 0040](0040-a-review-round-that-repeats-an-earlier-round-waits-for-the-person.md)). A fix that closing iDevelop interrupted waits for the person's Continue fix or Retry fix, one fix at a time in the implementers' order, and the other fixes of the round go on ([ADR 0013](0013-an-interrupted-fix-waits-for-the-person-s-choice.md)).

Source: the owner's report and decisions of 2026-10-25, which change their choice of 2026-10-20 in issue [#163](https://github.com/Mano-Liaoyan/iDevelop/issues/163).
